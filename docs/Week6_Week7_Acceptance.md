# 第六七周验收工具

项目界面统一使用 Vue，HTTP 接口由 FastAPI 提供。Streamlit 页面和对应依赖已移除。工具诊断属于测试工具，不出现在用户聊天界面，也不增加公开的诊断接口。

## Vue 中保留的业务能力

- 商品列表、详情、问答及引用由正式 `/api` 接口提供。
- 每次聊天发送 `follow_conversation: true`；使用后端响应中的商品 ID 同步商品卡片和网址。
- “那普通版呢”“Pro Max 呢”承接上一轮话题；切换商品保留同一会话编号，各商品完整历史仍由后端独立保存。
- 点击“新对话”才重置会话；回答标明所属商品并可展开引用原文。
- 第六周四类工具仍由后端选择。前端不直接读取业务 JSON，也不自行推断报价或售后。

## 离线回归

项目根目录执行 Python 测试，不调用真实聊天服务：

```text
uv run --no-sync python -m pytest -q
```

前端目录执行会话行为测试和构建：

```text
npm run test
npm run build
```

前端测试覆盖四轮连续请求、响应商品同步、手动切换保留会话、新对话重置、引用保留、重复发送保护和失败处理。Python 测试覆盖正式 API 约定及工具、缓存、商品过滤和记忆隔离。替身测试不代表真实模型验收通过。

## 独立真实验收

无需启动 Vue 或 FastAPI 进程。此工具直接调用正式 Agent，需要本地 BGE、商品向量库、Redis 和已配置的聊天服务，会产生实际模型调用。

先查看场景，不加载模型：

```text
uv run --no-sync python -m scripts.check_agent_acceptance --list
```

执行第六周或第七周，保存回答、引用及本轮真实工具过程：

```text
uv run --no-sync python -m scripts.check_agent_acceptance --suite week6 --report .cache/week6-acceptance.json
uv run --no-sync python -m scripts.check_agent_acceptance --suite week7 --report .cache/week7-acceptance.json
```

使用 `--suite all` 一次执行十个场景。退出码 0 表示全部检查通过，1 表示存在验收失败，2 表示运行环境未就绪。报告不得以工具路由成功代替事实、引用及商品隔离检查。

第六周六个场景为卖点、颜色、报价、七天退货、混合查询和不存在的规格。每次使用独立会话并绕过共享答案缓存，核对实际工具集合、商品范围、回答和引用；不存在的规格不得使用其他规格报价。

第七周四轮沿用同一会话：

| 轮次 | 问题 | 检查结果 |
| --- | --- | --- |
| 1 | 记住 WEEK7-PRO 并问 X500 Pro 无线充电 | Pro 演示资料最高 50W，保存备注 |
| 2 | 那普通版呢 | X500 不支持，功率不适用，问题不携带 Pro 备注 |
| 3 | Pro Max 呢 | 查询 Pro Max 自身依据，演示资料最高 50W |
| 4 | 回到 X500 Pro 询问备注 | 恢复 WEEK7-PRO，个人记忆不附商品引用 |

工具还会检查普通版的独立历史不包含 Pro 备注。所有验收使用随机会话，只清理自身的 Redis 记录、上下文索引和 SQLite 线程，不删除其他对话或共享数据。

## 第六周业务查询补齐

- 对明确的颜色、报价、售后问题，后端检查工具覆盖并补上模型漏掉的专用工具。混合询问三类信息时，必须实际执行三类工具；价格记录中的颜色字段不能代替商品信息查询。
- 简单业务字段根据本轮对应工具的结构化结果呈现。颜色、数量、SKU、金额和引用编号随真实字段变化；人民币分按整数换算，避免浮点误差。不存在的规格不使用其他规格或旧轮价格替代。
- 退货回答保留未激活、未使用、包装配件齐全及订单凭证等适用条件，不直接保证实际订单能够退货。
- 个人记忆、复杂参数与知识解释继续走原有回答流程，不以单一颜色或价格回答覆盖其他问题。错误商品、旧轮数据、异常业务字段均不得作为本轮可靠依据。
- 独立验收除路由外，还检查混合回答的颜色、金额以及售后条件。修改以上规则后升级答案缓存版本，避免旧回答绕过新逻辑。
- 单独询问商品卖点时，如果生成回答漏引用，仅在本轮检索确实存在当前商品的核心卖点章节时，改为展示该章节原文和真实引用；不会给模型编造的句子补来源，也不会拿旧轮或其他型号的片段兜底。

## 真实 FastAPI 业务工具与四轮验收

在项目根目录设置环境变量 `RUN_AGENT_INTEGRATION=1`，执行：

```text
uv run --no-sync python -m pytest tests/test_conversation_live.py -q -s
```

该测试分别执行第六周六个场景和第七周四轮场景，通过 FastAPI TestClient 发送与 Vue 相同的请求，运行真实模型、工具及存储；仅在测试内部采集执行过程，不改变公开响应字段。默认回归会跳过这两项，跳过不算验收通过。

## 通过 Vue 手工检查

启动 Redis、FastAPI 和 Vue 后，选择 X500 Pro，依次输入四轮问题，检查商品卡片、同一段聊天和引用。再手动切换商品、切回 Pro 询问备注；最后点击“新对话”，检查备注不能从上一会话继承。

商品数据均为项目演示设定，检查结果不代表品牌官方参数或商业承诺。替换模型或业务数据后应重新运行真实验收。
